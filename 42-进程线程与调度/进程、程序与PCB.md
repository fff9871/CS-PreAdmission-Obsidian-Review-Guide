# 进程、程序与PCB（★★★）

#operating-systems #process-management #process #pcb

## Overview Table

| 概念 | 核心含义 |
|---|---|
| 程序 | 静态的指令与数据集合 |
| 进程 | 程序在某个数据集合上的一次动态执行 |
| 进程映像 | 代码、数据、堆、栈、地址空间和内核管理状态 |
| PCB | 内核描述并管理进程的数据结构 |

## PCB 保存什么

| 类别 | 典型字段 |
|---|---|
| 标识 | PID、父进程、用户与组 |
| 处理机现场 | PC、通用寄存器、状态字、栈指针 |
| 调度 | 状态、优先级、时间片、队列链接 |
| 内存 | 页表根、段表或地址空间描述 |
| 资源 | 打开文件、信号、IPC、记账信息 |

    程序文件 + 输入数据
              ↓ 装载/创建
       地址空间 ↔ PCB ↔ 内核资源
              ↓ 调度
            CPU 执行

同一程序可以产生多个进程；同一进程也可通过动态链接、装载或执行新映像改变正在运行的程序。

> [!warning]
> PCB 不等于用户栈，也不等于整个进程映像。PCB 位于受保护的内核管理空间；进程“动态性”来自状态和资源随执行变化。

## Exam/Test Patterns

| 问法 | 回答 |
|---|---|
| 程序与进程 | 静态文件 vs 动态执行实体 |
| PCB 作用 | 保存现场、状态、资源和调度信息，是管理依据 |
| 多进程运行同一程序 | 代码可共享，但地址空间、现场和资源视图相互隔离 |
