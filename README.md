## 项目简介

本仓库将计算机专业课与相关数学基础整理为可检索、可链接、可主动回忆的 Obsidian 笔记。内容以知识点为最小单元，通过学习地图、速查页、易错点、来源映射和练习笔记串联，适合用于：

- 预推免、夏令营和保研面试前的系统复习；
- 专业课概念查漏补缺与高频问题速查；
- 使用双向链接建立跨课程知识网络；
- 基于练习页进行主动回忆和口述训练。

当前知识库覆盖 **9 个学科方向、55 个主题目录、36 个导航页和 380+ 篇 Markdown 笔记**。

### 知识库生成方式

本仓库由维护者使用 **`tutor-setup` Skill** 的 Document Mode，根据 PDF 学习资料生成并持续完善。该流程会先核对每份 PDF 的实际主题与页码，再建立完整知识清单，并统一生成 Dashboard、概念笔记、练习题、标签、来源映射和双向链接，使每个知识点都能追溯到对应资料。

仓库中的 `source_pdf`、`part`、学习地图、速查页、高频易错点和练习文件，均遵循 `tutor-setup` 的 StudyVault 组织规范。

## 组织方式

### 目录结构

```text
.
├── 00-Dashboard/                 # 九大学科的统一导航层
│   ├── *学习地图.md              # 学习顺序、主题入口与复习进度
│   ├── *速查.md                  # 核心定义、公式、算法与对比
│   ├── *高频易错点.md            # 易混概念、常见误区与口述修正
│   └── *来源映射与知识清单.md    # 资料来源、页码与覆盖范围
├── 01-概率基础/ ... 55-PyTorch与训练实践/
│   ├── 知识点.md                 # 单一主题的原子化知识笔记
│   └── 练习-主题名.md            # 主动回忆题与面试问答
├── .obsidian/                    # Obsidian 配置与 Git 同步插件
├── assets/                       # README 与项目视觉资源
└── README.md
```

### 四层知识导航

1. **学科层**：从 `00-Dashboard` 选择需要复习的课程。
2. **主题层**：按编号目录进入章节，例如 `34-传输层与TCP`。
3. **知识点层**：每篇笔记聚焦一个概念、算法、协议或常见问题。
4. **训练层**：通过 `练习-*`、高频易错点和学习地图中的复选框进行主动回忆。

### 单篇笔记结构

笔记通常包含以下元素：

- YAML 属性：`source_pdf`、`part`、`keywords`，用于记录来源与检索关键词；
- 标题与分层标签：标明学科、主题和笔记类型；
- 概览表或结论：优先给出面试时可直接口述的核心内容；
- 原理、步骤、公式、算法或时序图：解释知识点的完整逻辑；
- `Exam/Test Patterns`：整理常见问法、解题模式与回答要点；
- `Related Notes`：通过 Obsidian 双向链接连接前置知识和相邻主题。

### 编号与命名规则

- 顶层目录使用两位数字编号，保证文件浏览器中的课程顺序稳定；
- 普通知识笔记直接使用知识点名称，如 `TCP三次握手与连接建立.md`；
- 练习笔记使用 `练习-主题名.md`；
- Dashboard 每个学科固定包含“学习地图、速查、高频易错点、来源映射”四类入口；
- 内部链接使用 Obsidian Wiki Link，例如 `[[TCP拥塞控制算法]]`。

## 使用方式

### 方式一：直接在 GitHub 阅读

进入 [`00-Dashboard`](./00-Dashboard/) 后选择学科的“学习地图”。GitHub 可以直接渲染 Markdown、表格、代码块和相对链接，适合快速浏览与在线查阅。

### 方式二：使用 Obsidian 打开

1. 安装 [Obsidian](https://obsidian.md/) 和 [Git](https://git-scm.com/)。
2. 克隆仓库：

   ```bash
   git clone https://github.com/fff9871/CS-PreAdmission-Obsidian-Review-Guide.git
   ```

3. 在 Obsidian 中选择“打开本地仓库”，打开克隆得到的目录。
4. 首次打开时确认信任仓库，并启用已随仓库提供的 `Obsidian Git` 社区插件。
5. 从 `00-Dashboard` 中的学习地图开始复习。

### 推荐复习流程

1. **建立框架**：阅读对应学科的学习地图，明确章节顺序和知识边界。
2. **理解知识点**：按主题目录逐篇阅读，并沿 `Related Notes` 补齐前置知识。
3. **压缩记忆**：使用速查页复述定义、公式、算法复杂度和协议过程。
4. **主动回忆**：关闭正文后完成 `练习-*` 中的问题，再回看答案校正表达。
5. **集中纠错**：复习高频易错点，并在学习地图中维护个人薄弱项和完成状态。

### Obsidian 功能建议

- 使用全局搜索组合关键词、标签和文件夹定位内容；
- 使用关系图谱观察课程内部及跨课程链接；
- 使用反向链接查找某个知识点被哪些专题引用；
- 将面试前需要重点复习的页面加入书签；
- 在本地分支记录个人补充，定期通过 Git 保留历史版本。

## 贡献方式

欢迎通过 Issue 和 Pull Request 补充知识点、修正表述、完善来源或新增练习。

### 使用 `tutor-setup` 从 PDF 贡献

新增学科、章节或成体系扩展知识点时，请使用 **`tutor-setup` Skill** 的 Document Mode，根据 PDF 生成内容，以保持来源追踪、笔记深度和仓库结构一致。

1. 将有权使用的 PDF 放入当前工作目录或其子目录。
2. 在支持 Codex Skills 的环境中调用：

   ```text
   $tutor-setup <PDF 路径>
   ```

3. 确认使用 Document Mode，并核对 Skill 扫描得到的资料列表、实际主题和页码范围。
4. 按完整主题清单生成或更新以下内容：
   - 学习地图、速查页、高频易错点和来源映射；
   - 带 `source_pdf`、`part`、`keywords` 的概念笔记；
   - 每个主题目录的主动回忆练习；
   - 概念、练习与 Dashboard 之间的双向链接。
5. 完成 `tutor-setup` 自检，并人工复核事实、公式、术语、链接和资料页码。

PDF 仅作为知识整理来源。提交时请保留可追溯的资料名称和页码，并遵守资料版权与授权范围。

### 标准流程

1. Fork 本仓库并克隆自己的副本。
2. 基于 `main` 创建分支：

   ```bash
   git checkout -b docs/add-topic-name
   ```

3. 使用 `tutor-setup` 根据 PDF 生成或更新 StudyVault 内容。
4. 检查 Wiki Link、Markdown 表格、标题层级、练习覆盖和来源信息。
5. 提交并推送分支：

   ```bash
   git add .
   git commit -m "docs: 补充主题名称"
   git push -u origin docs/add-topic-name
   ```

6. 发起 Pull Request，说明修改范围、资料来源和验证方式。

### 内容规范

- **一篇一主题**：避免把多个独立知识点堆叠在同一篇笔记中；
- **结论先行**：先给可复述结论，再补充推导、原理和边界条件；
- **来源可追溯**：在 YAML 中填写资料名、章节或页码；
- **链接可导航**：补充前置知识、相邻主题、练习页和 Dashboard 链接；
- **术语一致**：优先沿用仓库已有命名，并在首次出现时给出英文或缩写；
- **面试导向**：突出常见问法、对比项、易错点和回答结构；
- **尊重版权**：提交整理后的知识表达、引用信息和必要摘录，不上传未获授权的完整资料。

### Pull Request 检查清单

- [ ] 新增或成体系扩展的内容已使用 `tutor-setup` Document Mode 根据 PDF 生成；
- [ ] Pull Request 已说明 PDF 资料名称、实际主题和页码范围；
- [ ] 文件位于正确的编号目录，名称清晰且唯一；
- [ ] YAML、标签和标题格式与相邻笔记一致；
- [ ] 新增 Wiki Link 在 Obsidian 中可以正确解析；
- [ ] 新主题已加入对应学习地图或来源映射页；
- [ ] 事实、公式、代码和协议描述已经核对；
- [ ] 提交只包含本次贡献相关文件。

## 同步方式

仓库使用 GitHub 保存版本历史，并通过 `Obsidian Git` 插件完成日常自动同步。当前配置位于 [`.obsidian/plugins/obsidian-git/data.json`](./.obsidian/plugins/obsidian-git/data.json)。

### 自动同步策略

| 环节 | 当前策略 |
|---|---|
| 启动同步 | 打开 Obsidian 仓库时自动拉取远程更新 |
| 定时拉取 | Obsidian 运行期间每 10 分钟拉取一次 |
| 自动备份 | 每 10 分钟创建提交并推送到远程仓库 |
| 推送前处理 | 推送前先拉取远程更新，降低非快进冲突概率 |
| 提交信息 | `vault backup: YYYY-MM-DD HH:mm:ss` |
| 本地状态 | 工作区布局、缓存和系统文件通过 `.gitignore` 排除 |

自动同步依赖 Obsidian 保持运行、Git 凭据有效且网络可访问 GitHub。编辑完成后，可观察 Obsidian 状态栏中的分支和同步状态，确认提交已经推送。

### 手动同步

需要立即同步时，可以在 Obsidian 命令面板执行 `Obsidian Git: Create backup`，也可以在终端运行：

```bash
git pull --rebase origin main
git add .
git commit -m "docs: 更新复习笔记"
git push origin main
```

### 多设备协作建议

1. 开始编辑前先拉取最新版本；
2. 避免多台设备同时修改同一篇笔记；
3. 编辑结束后等待自动备份完成，或执行一次手动同步；
4. 发生冲突时保留双方有效内容，检查 Wiki Link 后再提交；
5. 个人工作区状态不进入版本库，各设备可独立维护界面布局。
