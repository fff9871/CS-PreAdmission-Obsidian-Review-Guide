# 计算机系统层次、编译解释与程序执行（★★★）

#computer-organization #computer-system #stored-program

## Overview Table

| 层次/阶段 | 输入 | 输出/作用 |
|---|---|---|
| 高级语言 | 源程序 | 便于表达算法 |
| 编译/解释 | 源代码 | 目标代码或即时执行结果 |
| 汇编 | 汇编语言 | 可重定位目标文件 |
| 链接 | 目标文件与库 | 可执行文件 |
| 装载 | 可执行文件 | 内存中的进程映像 |
| 指令执行 | 机器指令 | 数据通路上的微操作序列 |

## 编译与解释

| 方式 | 特点 | 边界 |
|---|---|---|
| 编译 | 执行前把较大程序单元翻译成目标代码 | 运行快，但需生成/装载目标程序 |
| 解释 | 运行时逐步分析并执行 | 灵活，传统实现重复翻译开销较大 |
| 混合/JIT | 中间表示配合运行时热点编译 | 兼顾移植性与性能，但运行时复杂 |

## 从源码到执行

    source.c
       ↓ 预处理
    source.i
       ↓ 编译
    source.s
       ↓ 汇编
    source.o + libraries
       ↓ 链接
    executable
       ↓ 装载
    主存中的代码/数据 → CPU取指执行

程序运行时，ISA 是软件与硬件之间的关键接口：编译器生成符合 ISA 的指令，处理器用具体微体系结构实现这些指令。

> [!warning]
> “解释型语言不编译”是过度简化。许多语言实现会先生成字节码、使用 JIT 或混合执行；语言规范与某个具体实现应分开讨论。

## Exam/Test Patterns

| 关键词 | 回答 |
|---|---|
| `.c` 到可执行文件 | 预处理、编译、汇编、链接 |
| ISA 作用 | 规定指令、寄存器、数据类型和可见行为，是软硬件接口 |
| 装载 | 将可执行映像映射到地址空间并准备运行环境 |
