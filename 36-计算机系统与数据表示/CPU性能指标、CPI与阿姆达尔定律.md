# CPU性能指标、CPI与阿姆达尔定律（★★★）

#computer-organization #computer-system #performance #cpi #amdahl-law

## Overview Table

| 指标 | 公式/含义 | 注意点 |
|---|---|---|
| 时钟周期 T | `T=1/f` | 主频高不必然程序更快 |
| CPI | 平均每条指令所需时钟周期数 | 与程序、ISA、微结构相关 |
| CPU 时间 | `IC × CPI × T = IC × CPI / f` | 比较程序性能的核心公式 |
| IPC | 每周期完成指令数 | 理想近似为 `1/CPI`，超标量可大于 1 |
| MIPS | `IC/(执行时间×10⁶)` | 跨 ISA 比较可能误导 |
| 加速比 | `旧执行时间/新执行时间` | 性能与执行时间成反比 |

## 系统级指标边界

| 指标 | 说明 |
|---|---|
| 机器字长 | 一次定点整数运算常处理的位数，通常关联寄存器与加法器宽度 |
| 数据通路宽度 | 总线或内部通路一次并行传送的位数 |
| 主存容量 | 可寻址并实际配置的主存规模 |
| 响应时间 | 完成单个任务所需时间 |
| 吞吐量 | 单位时间完成的任务数量 |

## 阿姆达尔定律

若可优化部分占原执行时间比例 `p`，该部分加速 `s` 倍：

`总加速比 = 1 / ((1-p) + p/s)`

即使局部加速无限大，总加速比也不超过 `1/(1-p)`。优化应优先针对占用时间大的公共路径。

    原时间 = 不可优化部分 + 可优化部分
            (1-p)         p
    新时间 = (1-p) + p/s

## 性能比较方法

- 固定工作负载，比较执行时间或吞吐量。
- 将 IC、CPI、主频三个因素共同考虑。
- 浮点密集任务可参考 FLOPS，但不能代表所有程序。
- 基准测试需要说明数据集、编译选项、缓存预热和功耗约束。

> [!warning]
> 主频、MIPS、核数都不是独立充分的性能指标。提高主频可能伴随更深流水线和功耗增加；不同 ISA 的一条“指令”完成工作量也不同。

## Exam/Test Patterns

| 场景 | 回答步骤 |
|---|---|
| 比较两台 CPU | 分别计算 `IC×CPI/f`，不要只看主频 |
| 局部优化 | 用阿姆达尔定律评估总收益 |
| 多核加速 | 先识别可并行比例和串行瓶颈 |
