# 冯诺依曼结构、哈佛结构与存储程序（★★★）

#computer-organization #computer-system #von-neumann #stored-program

## Overview Table

| 架构/概念 | 指令与数据存储 | 通路特点 | 典型影响 |
|---|---|---|---|
| 冯诺依曼结构 | 共享存储空间 | 指令与数据常共享总线 | 结构统一，可能形成访存瓶颈 |
| 哈佛结构 | 指令与数据分离 | 可并行取指与访数 | 带宽高，地址空间和硬件更复杂 |
| 改进型哈佛 | 高层统一地址空间，一级缓存分离 | I-Cache 与 D-Cache 可并行 | 现代处理器常见折中 |
| 存储程序 | 程序和数据以二进制存入存储器 | CPU 逐条取指执行 | 软件可修改、装载和复用硬件 |

## 冯诺依曼机五大部件

- **运算器**：算术、逻辑、移位等数据加工。
- **控制器**：取指、译码并产生控制信号。
- **存储器**：保存程序和数据。
- **输入设备、输出设备**：实现人与外部环境的信息交换。

    输入 → 存储器 ↔ 运算器 → 输出
              ↑       ↕
              └── 控制器

## 存储程序工作方式

1. 程序和数据预先装入主存。
2. PC 指向下一条指令地址。
3. CPU 取指、译码、执行并形成后继 PC。
4. 分支、中断和异常可改变顺序执行路径。

> [!warning]
> “指令和数据同等存放”不代表二者语义相同；CPU 依据当前执行阶段和控制信号解释比特。现代系统也常在缓存层采用哈佛式分离，不能只用一张经典框图概括全部实现。

## Exam/Test Patterns

| 问法 | 回答路径 |
|---|---|
| 冯诺依曼特点 | 五部件、二进制、存储程序、按地址访问、通常顺序执行 |
| 哈佛 vs 冯诺依曼 | 存储空间和通路是否分离、带宽与复杂度权衡 |
| 冯诺依曼瓶颈 | CPU 与存储器之间共享通路限制吞吐 |
