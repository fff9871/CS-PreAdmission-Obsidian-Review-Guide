# 系统调用、API与参数传递（★★★）

#operating-systems #os-fundamentals #system-calls

## Overview Table

| 概念 | 所在层次 | 说明 |
|---|---|---|
| API/库函数 | 用户空间接口 | 便于编程，可能完全在用户态完成 |
| 系统调用 | 用户态请求内核服务的受控接口 | 触发陷入，按编号分派 |
| 内核服务例程 | 内核内部实现 | 检查参数、权限并操作资源 |
| ABI | 二进制约定 | 规定参数寄存器、栈、返回值和调用号 |

## 调用路径

    app → libc/API wrapper
          ↓ 准备调用号与参数
       syscall/trap 指令
          ↓ 切换内核态
       分派表 → sys_xxx → 返回值/errno
          ↓
       恢复用户态

参数可通过寄存器、用户栈或用户内存块传递。内核必须复制或校验用户指针，防止无效地址和 TOCTOU 风险。

## API 与系统调用的关系

一个库函数可能封装一个或多个系统调用，也可能无须系统调用；一个系统调用也可被不同高级 API 使用。例如格式化字符串通常在用户库处理，最终写出数据时才调用内核。

> [!warning]
> 系统调用不是普通函数调用：它涉及特权级转换和内核入口，但不必然导致线程阻塞或进程调度。系统调用也不是“软中断”的唯一实现，现代架构常有专用 syscall 指令。

## Exam/Test Patterns

| 问法 | 回答 |
|---|---|
| 库函数 vs 系统调用 | 用户层封装 vs 受控进入内核的机制 |
| 参数如何传 | 寄存器、栈或内存，按 ABI 约定并由内核校验 |
| 系统调用开销 | 模式切换、参数检查、缓存/TLB影响及实际服务成本 |
