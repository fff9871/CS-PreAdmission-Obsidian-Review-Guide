# 用户态、内核态与特权指令（★★★）

#operating-systems #os-fundamentals #kernel-mode #user-mode

## Overview Table

| 模式 | 可执行操作 | 典型代码 |
|---|---|---|
| 用户态 | 受限指令与受保护地址空间 | 普通应用、用户库 |
| 内核态 | 特权指令、设备和内核地址空间 | 调度、内存、驱动、文件系统核心 |
| 特权指令 | 修改中断、页表、I/O 控制等敏感状态 | 只能由内核执行 |

## 受控切换

    用户程序
      ├─ syscall/trap ─┐
      ├─ exception ────┼→ 硬件保存关键状态 → 内核入口
      └─ interrupt ────┘
                              ↓ 处理
                       恢复状态并返回用户态

CPU 模式位与页表权限共同形成保护边界。用户代码必须通过受控入口请求内核服务，而不能直接修改关键硬件状态。

## 为什么需要双态

- 隔离错误和恶意程序，保护内核与其他进程。
- 对共享资源实施统一检查、授权与记账。
- 让异常和中断能转入可信处理代码。

> [!warning]
> 用户态/内核态切换不等于进程切换。系统调用可能在同一进程上下文中进入内核并返回；只有调度到另一个进程时才发生进程上下文切换。

## Exam/Test Patterns

| 关键词 | 回答 |
|---|---|
| 特权指令 | 只能在内核态执行，避免破坏系统状态 |
| 模式切换 | syscall、异常或中断触发硬件受控入口 |
| 与上下文切换区别 | 模式改变可不换进程，进程切换必然更换执行上下文 |
