# 网络性能指标、时延与吞吐量（★★★）

#computer-networks #network-architecture #network-performance #delay #throughput

## Overview Table

| 指标 | 含义 | 常见单位/公式 |
|---|---|---|
| 速率 | 单位时间传送的比特数 | bit/s |
| 带宽 | 链路可支持的最高数据率；模拟语境也可指频带宽度 | bit/s 或 Hz |
| 吞吐量 | 实际单位时间成功传送的数据量 | bit/s |
| 发送时延 | 将分组全部推入链路所需时间 | `L / R` |
| 传播时延 | 信号跨越介质所需时间 | `d / v` |
| 排队时延 | 分组等待输出链路的时间 | 随负载变化 |
| 处理时延 | 检查首部、差错和选路所需时间 | 设备相关 |

## 总时延与时延带宽积

`节点总时延 = 处理时延 + 排队时延 + 发送时延 + 传播时延`

`时延带宽积 = 传播时延 × 链路带宽`

时延带宽积可理解为“链路管道中能容纳的在途比特数”。往返时延 RTT 则是报文到达对端并返回响应的大致时间，是 TCP 超时与窗口设计的重要依据。

    长分组 L bit --以 R bit/s 推入--> 链路 --距离 d--> 接收端
                    发送时延 L/R       传播时延 d/v

## 易混指标

| 对比 | 判断 |
|---|---|
| 带宽 vs 吞吐量 | 前者偏能力上限，后者偏实际结果 |
| 发送时延 vs 传播时延 | 前者与分组长度、速率有关；后者与距离、传播速度有关 |
| RTT vs 单向时延 | RTT 包含往返路径及沿途处理，通常不等于单向时延的精确两倍 |

> [!warning]
> 增大带宽会降低发送时延，但不直接改变传播时延；链路空闲时排队时延接近零，高负载时可能急剧增大。

## Exam/Test Patterns

| 场景/关键词 | 回答 |
|---|---|
| 给定 L、R、d、v | 分别算 `L/R` 与 `d/v`，再按路径节点累加 |
| “提高带宽能否消除延迟” | 只能改善发送与部分排队时延，不能消除传播和处理时延 |
| 时延带宽积 | 表示链路中的在途数据量，不是已成功交付量 |
