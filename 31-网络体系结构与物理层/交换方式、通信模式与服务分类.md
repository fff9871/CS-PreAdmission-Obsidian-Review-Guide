# 交换方式、通信模式与服务分类（★★★）

#computer-networks #network-architecture #packet-switching #network-services

## Overview Table

| 维度 | 类型 | 核心区别 |
|---|---|---|
| 交换方式 | 电路、报文、分组交换 | 是否预留路径、存储转发粒度 |
| 通信方向 | 单工、半双工、全双工 | 数据可否双向、能否同时双向 |
| 服务连接 | 面向连接、无连接 | 通信前是否先建立逻辑关系 |
| 服务质量 | 可靠、不可靠 | 是否提供确认、重传、顺序等保证 |
| 交付对象 | 单播、广播、组播 | 一个、全部或一组接收者 |

## 三种交换方式

| 方式 | 过程 | 优点 | 代价/场景 |
|---|---|---|---|
| 电路交换 | 建立连接→独占资源→传输→释放 | 连续、时延稳定 | 建立慢，突发数据利用率低 |
| 报文交换 | 整个报文逐节点存储转发 | 不需预留专线 | 缓冲大、等待长 |
| 分组交换 | 报文切成小分组独立或按虚电路转发 | 共享效率高、适合突发流量 | 有首部、排队、乱序风险 |

      ├─ 分组 P2 ─┼─ 共享链路逐跳转发

## 连接与可靠性是不同维度

- 面向连接不等于一定可靠；无连接也可由上层补充可靠机制。
- TCP 是面向连接、可靠的传输服务；UDP 是无连接、尽最大努力的传输服务。
- IP 是无连接、尽最大努力的数据报服务，但端系统可通过 TCP 获得可靠字节流。

> [!warning]
> “分组交换”也分数据报方式和虚电路方式。虚电路需要先建立逻辑路径，但链路资源通常仍与其他通信共享，不等同于电路交换的物理资源独占。

## Exam/Test Patterns

| 场景/关键词 | 回答 |
|---|---|
| 突发计算机数据 | 通常选分组交换，强调统计复用 |
| 电话网与互联网 | 传统电话偏电路交换，互联网核心偏分组交换 |
| 面向连接 vs 可靠 | 分别回答连接建立与交付保证，不能互相替代 |
