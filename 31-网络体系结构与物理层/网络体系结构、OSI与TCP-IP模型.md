# 网络体系结构、OSI与TCP-IP模型（★★★）

#computer-networks #network-architecture #osi-model #tcp-ip-model

## Overview Table

| 模型 | 层次 | 核心定位 |
|---|---|---|
| OSI | 物理、数据链路、网络、传输、会话、表示、应用 | 理论参考模型，层次边界细 |
| TCP/IP | 网络接口、网际、传输、应用 | 互联网工程模型，围绕 IP 互联 |
| 五层模型 | 物理、数据链路、网络、传输、应用 | 教学中兼顾两者，便于定位协议与设备 |

## 为什么分层

- 每层只解决一类问题，通过接口使用下层服务。
- 协议描述**同层实体**如何通信，服务描述**下层向上层**提供什么能力。
- 分层有利于模块替换、标准化、故障定位和异构网络互联。

    应用数据
       ↓ 加首部
    传输层报文段
       ↓
    网络层数据报
       ↓
    链路层帧
       ↓
    物理层比特流

> [!important]
> 对等层之间是“逻辑通信”；实际数据仍逐层向下发送、跨介质传输，再在接收端逐层向上解封装。

## 层、协议与典型对象

| 层 | 主要任务 | 典型协议/设备 | 数据单位 |
|---|---|---|---|
| 应用层 | 面向应用提供网络服务 | HTTP、DNS、FTP、SMTP | 报文 |
| 传输层 | 进程到进程通信 | TCP、UDP | 报文段/用户数据报 |
| 网络层 | 主机到主机、路由与转发 | IP、ICMP、路由器 | 数据报/分组 |
| 数据链路层 | 相邻节点帧传输 | Ethernet、PPP、交换机 | 帧 |
| 物理层 | 透明传输比特 | 中继器、集线器 | 比特 |

> [!warning]
> 协议分层是逻辑抽象。现代设备可能同时处理多层信息，例如三层交换机既能完成链路层交换，也能进行 IP 转发。

## Exam/Test Patterns

| 场景/关键词 | 回答路径 |
|---|---|
| OSI 与 TCP/IP 对应 | 先列层次，再说明会话层和表示层通常并入 TCP/IP 应用层 |
| 为什么分层 | 独立性、接口、标准化、易维护；同时指出首部开销与跨层优化代价 |
| 网络层与传输层 | 前者主机到主机，后者进程到进程 |
