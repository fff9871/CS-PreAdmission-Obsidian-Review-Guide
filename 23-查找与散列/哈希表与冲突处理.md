# 哈希表与冲突处理（★★★）

#data-structures #searching #hashing

## Overview Table

| 冲突策略 | 做法 | 优点 | 注意 |
|---|---|---|---|
| 分离链接 | 每个桶挂链表/其他容器 | 删除自然，负载因子可超过 1 | 指针与缓存局部性开销 |
| 线性探测 | 逐格寻找空位 | 连续访问、缓存友好 | 主聚集 |
| 二次探测 | 按平方偏移探测 | 缓解主聚集 | 未必遍历所有桶 |
| 双重散列 | 第二哈希函数给步长 | 分布通常更好 | 步长应与表长互质 |

## 核心量

负载因子 $\alpha=n/m$，其中 $n$ 是元素数，$m$ 是桶数。$\alpha$ 增大会使冲突增多，因此开放定址通常在达到阈值时扩容并 **rehash**。

```text
key → hash(key) → bucket
                    ├─ 无冲突：直接存放
                    └─ 有冲突：链接或按探测序列寻址
```

## 构造哈希函数

目标是计算快、分布均匀、尽量使用关键字全部信息。常见有除留余数法、乘法、字符串滚动哈希等。

> [!warning]
> 平均 $O(1)$ 不是最坏 $O(1)$。若所有键冲突到一处，查找可退化为 $O(n)$；安全场景还需考虑恶意构造的哈希冲突。

## Exam/Test Patterns

| 提问 | 回答 |
|---|---|
| 为何需要扩容 | 控制负载因子，降低期望探测长度 |
| 开放定址如何删除 | 使用墓碑标记，不能直接置空以免截断探测链 |
| 哈希函数好坏 | 看均匀性、计算代价、对输入模式的敏感性 |
