# 中断响应、优先级与向量（★★★）

#computer-organization #io-system #interrupt #interrupt-priority #interrupt-vector

## Overview Table

| 概念 | 含义 |
|---|---|
| 中断请求 | 设备或事件向 CPU 提出服务需求 |
| 中断响应优先级 | 多个请求同时到达时先响应谁，常由硬件/查询顺序决定 |
| 中断处理优先级 | 服务期间谁可打断谁，可由屏蔽字等控制 |
| 中断向量 | 对应中断服务程序入口地址 |
| 向量地址/类型号 | 在向量表中定位表项的信息 |
| 向量中断 | 通过硬件/协议获得向量并定位服务程序 |

## 中断处理流程

    指令执行结束
       ↓ 检查未屏蔽请求
    中断响应：关中断/保存断点/取得向量
       ↓
    中断服务程序：保护现场→服务设备→恢复现场
       ↓
    中断返回：恢复PC与状态

硬件通常完成关中断、保存断点和转入入口等中断隐指令；软件服务程序保存通用现场、处理中断源并恢复。

## 中断与子程序

| 维度 | 中断 | 子程序调用 |
|---|---|---|
| 发生时机 | 外部中断通常异步、不可预知 | CALL 位置由程序确定 |
| 服务对象 | 系统/设备事件 | 主程序功能分解 |
| 入口 | 向量或异常机制确定 | 指令显式给出目标 |
| 支持 | 软硬件协同 | 主要是指令与软件约定 |

> [!warning]
> 外中断通常在指令边界响应，但异常可能由当前指令同步触发。精确异常要求保存的状态足以让处理后正确重启或继续执行。

## Exam/Test Patterns

| 问法 | 回答 |
|---|---|
| 响应优先级 vs 处理优先级 | 同时请求先选谁 vs 服务中谁能打断谁 |
| 中断向量 vs 向量地址 | ISR 入口地址 vs 定位入口的表项地址/编号 |
| 中断与子程序 | 异步软硬件事件 vs 程序预先安排的调用 |
