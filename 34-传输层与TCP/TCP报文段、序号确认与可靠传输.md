# TCP报文段、序号确认与可靠传输（★★★）

#computer-networks #transport-layer #tcp #tcp-reliability

## Overview Table

| 机制 | 作用 |
|---|---|
| 序号 | 标识字节流中数据位置，支持排序与去重 |
| 确认号 | 累计确认下一个期望字节 |
| 校验和 | 检测首部和数据差错 |
| 超时重传 | 未及时确认时重发 |
| 快重传 | 收到多个重复 ACK 后提前重发疑似丢失段 |
| 滑动窗口 | 允许多个报文段在途并实施流量控制 |

## 面向字节流

TCP 不保留应用写入的消息边界：一次 `send` 的数据可能分成多个段，也可能与其他写入合并交付。应用若需要消息边界，应设计长度字段、分隔符或固定长度协议。

    字节流: 0 1 2 3 4 5 6 ...
             └─段A─┘ └─段B─┘
    ACK = k 表示 k 之前的连续字节已收到，下一字节期望 k

## 重传超时

RTO 应根据测量的 RTT 平滑估计并保留波动余量。过短会产生伪重传，过长会延迟丢包恢复。TCP 常使用 Karn 思想避免从重传段获得歧义 RTT 样本，并采用指数退避。

> [!warning]
> TCP 的可靠性是“连接两端所见字节流按序且不重复”，不代表应用事务一定正确，也不保证网络中绝不丢包；丢包由端系统检测并恢复。ACK 通常是累计确认，SACK 是可选增强。
