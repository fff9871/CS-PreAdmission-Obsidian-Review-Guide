# TCP滑动窗口与流量控制（★★★）

#computer-networks #transport-layer #tcp #flow-control #sliding-window

## Overview Table

| 量 | 含义 | 由谁反映/决定 |
|---|---|---|
| `rwnd` | 接收方当前可用缓冲能力 | 接收方通告 |
| `cwnd` | 网络拥塞允许的发送量估计 | 发送方拥塞算法维护 |
| 发送窗口 | 实际可在途数据上限 | 通常受 `min(rwnd, cwnd)` 限制 |
| ACK | 推进已确认字节边界 | 接收方累计确认 |

## 滑动过程

    [已确认][已发送未确认][可立即发送][窗口外]
              <--------- 发送窗口 -------->

ACK 到达后左边界右移；应用读取接收缓冲后，接收方可通告更大的 `rwnd`。接收窗口为 0 时，发送方用持续计时器定期发送窗口探测，避免窗口更新报文丢失后双方永久等待。

## 流量控制的目标

流量控制解决**发送方与接收方处理速度不匹配**，保护接收缓冲；它是端到端问题。Nagle 算法、延迟 ACK 等会影响小报文交互，但与窗口通告的核心目标不同。

> [!warning]
> `rwnd` 大不代表网络一定能承载相同速率；实际发送还受 `cwnd`、路径容量、应用供数速度和实现限制。流量控制不能替代拥塞控制。

## Exam/Test Patterns

| 关键词 | 回答 |
|---|---|
| 接收方来不及处理 | 通过通告 `rwnd` 限制发送窗口 |
| 零窗口 | 停止正常发送并周期探测窗口更新 |
| 实际窗口 | 通常受 `min(rwnd,cwnd)` 约束 |
