# TCP拥塞控制算法（★★★）

#computer-networks #transport-layer #tcp #congestion-control

## Overview Table

| 算法/阶段 | 触发与行为 |
|---|---|
| 慢开始 | `cwnd` 较小时，每个 RTT 近似指数增长 |
| 拥塞避免 | 达到 `ssthresh` 后加法增大，约每 RTT 增 1 MSS |
| 超时处理 | 认为拥塞严重，降低门限并把 `cwnd` 降到很小后重新慢开始 |
| 快重传 | 多个重复 ACK 提示某段丢失，未等 RTO 即重传 |
| 快恢复 | 重复 ACK 场景下减小窗口后继续拥塞避免，具体依 TCP 版本 |

## 典型状态变化

    cwnd
      ↑      /\/  拥塞避免：线性增长
      |    /
      |  /       重复ACK → 快重传/快恢复
      |/         超时 → 更强降窗并慢开始
      +------------------------------→ time

## 流量控制与拥塞控制

| 对比 | 流量控制 | 拥塞控制 |
|---|---|---|
| 保护对象 | 接收方缓冲 | 整个网络路径 |
| 主要信号 | 接收窗口 `rwnd` | 丢包、ECN、RTT 等拥塞信号 |
| 主要变量 | 接收窗口 | 拥塞窗口 `cwnd` |

> [!warning]
> “慢开始”指初始窗口较小，不是增长慢；它通常按 ACK 增长，近似每 RTT 翻倍。现代 TCP 版本如 CUBIC、BBR 的细节不完全等同于经典 Reno，但面试基础题常以慢开始、拥塞避免、快重传和快恢复为主。

## Exam/Test Patterns

| 场景 | 回答 |
|---|---|
| 超时 | 强拥塞信号，门限减小并重新慢开始 |
| 三个重复 ACK | 快重传，经典 Reno 进入快恢复 |
| 流量 vs 拥塞 | 接收端能力 vs 网络承载能力 |
