# IP地址、MAC地址与ARP（★★★）

#computer-networks #network-layer #ipv4 #arp #mac-address

## Overview Table

| 地址 | 层次 | 作用域 | 转发中的变化 |
|---|---|---|---|
| IP 地址 | 网络层 | 跨网络的逻辑寻址 | 普通端到端转发中保持不变 |
| MAC 地址 | 数据链路层 | 当前链路上的帧交付 | 每经过一台路由器重新封装 |
| 端口号 | 传输层 | 主机中的应用进程 | 标识通信端点的进程 |

## ARP 工作过程

当主机需要在本地链路发送 IPv4 分组，却只知道下一跳 IP：

    查 ARP 缓存
      ├─ 命中 → 直接封装目的MAC
      └─ 未命中 → 广播 ARP Request
                         ↓
                    目标单播 Reply
                         ↓
                    缓存 IP→MAC

若目的 IP 不在本子网，主机解析的是**默认网关接口**的 MAC，而不是远端主机 MAC。

## 跨网封装

| 跳次 | 帧源 MAC | 帧目的 MAC | IP 源/目的 |
|---|---|---|---|
| 主机→网关 | 主机 MAC | 网关 MAC | 源主机 IP / 远端 IP |
| 路由器→下一跳 | 出接口 MAC | 下一跳 MAC | 通常仍为源主机 IP / 远端 IP |

> [!warning]
> ARP 只解析同一广播域内的 IPv4 下一跳地址。它不是域名解析，也不能跨越路由器广播。IPv6 使用邻居发现协议 NDP，而不是 ARP。

## Exam/Test Patterns

| 问法 | 回答 |
|---|---|
| 远端通信时 ARP 查谁 | 查默认网关/下一跳的 MAC |
| IP 与 MAC 区别 | 分层逻辑地址 vs 本地链路硬件地址 |
| ARP 安全风险 | 无认证，可能被欺骗污染缓存 |
