# 视图、存储过程与触发器（★★★）

#database #sql #database-objects

## Overview Table

| 项目 | 要点 |
|---|---|
| 视图 | 保存查询定义的逻辑表，普通视图通常不保存结果 |
| 物化视图 | 保存查询结果，需要刷新 |
| 存储过程 | 数据库内可参数化调用的程序单元 |
| 触发器 | 由表或数据库事件自动触发的程序 |

## 用途比较

| 对象 | 常见用途 | 主要代价 |
|---|---|---|
| 视图 | 封装查询、权限隔离、简化接口 | 复杂视图可能难优化或不可更新 |
| 存储过程 | 封装多步数据库操作、减少往返 | 可移植性和调试成本 |
| 触发器 | 审计、派生数据、强化规则 | 隐式副作用，调用链难排查 |

## 视图可更新性

单表简单视图通常较容易更新；含聚合、DISTINCT、集合运算或复杂连接的视图往往不可直接更新，具体规则依 DBMS。

## 设计原则

关键业务约束优先用声明式约束表达；触发器用于约束难以直接表达或必须自动响应事件的场景。

> [!warning]
> 普通视图不是数据副本，也不会天然提高性能；物化视图才存储结果，但要处理刷新与一致性。

## Exam/Test Patterns

| 场景/关键词 | 回答 |
|---|---|
| 视图与物化视图 | 一个保存定义，一个保存结果 |
| 触发器风险 | 隐式执行、递归触发、顺序依赖和维护困难 |
| 存储过程优缺点 | 减少往返与集中逻辑，但耦合数据库产品 |
