# 多表连接、子查询与集合运算（★★★）

#database #sql #join

## Overview Table

| 项目 | 要点 |
|---|---|
| INNER JOIN | 只保留满足连接条件的组合 |
| LEFT JOIN | 保留左表全部行，未匹配右侧补 NULL |
| 子查询 | 把一个查询作为表达式、集合或派生表 |
| UNION | 合并并去重 |
| UNION ALL | 合并并保留重复 |

## 外连接过滤陷阱

LEFT JOIN 后若在 WHERE 中要求右表列满足普通条件，会过滤掉右侧为 NULL 的行，结果可能退化为内连接。若希望保留左表行，应考虑把右表条件放到 ON。

## EXISTS 与 IN

EXISTS 表达“是否存在匹配行”，适合相关子查询；IN 表达成员关系。优化器常可改写两者，但 NULL 语义尤其会影响 NOT IN。

## 连接算法

嵌套循环适合小外表或有索引内表；哈希连接适合等值连接；排序归并连接适合已排序输入或范围/等值场景。

> [!warning]
> NOT IN 子查询若包含 NULL，三值逻辑可使结果全部为 UNKNOWN；反连接更稳妥地使用 NOT EXISTS 并写清关联条件。

## Exam/Test Patterns

| 场景/关键词 | 回答 |
|---|---|
| LEFT JOIN 条件位置 | ON 决定匹配，WHERE 再过滤结果 |
| UNION 与 UNION ALL | 前者去重并有额外代价，后者直接拼接 |
| N+1 查询 | 批量连接或一次查询代替循环发 SQL |
