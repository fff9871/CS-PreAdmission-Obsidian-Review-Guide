# 数据库系统、三级模式与二级映像（★★★）

#database #database-systems #schema-architecture

## Overview Table

| 项目 | 要点 |
|---|---|
| 数据库系统 | 数据库、DBMS、应用程序和用户的整体 |
| 外模式 | 用户或应用看到的局部逻辑视图 |
| 模式 | 全体数据的全局逻辑结构 |
| 内模式 | 物理存储结构与存取方式 |

## 三级模式与二级映像

外模式 --外模式/模式映像--> 模式 --模式/内模式映像--> 内模式

外模式/模式映像支撑逻辑独立性；模式/内模式映像支撑物理独立性。

## 数据库系统特点

- 数据结构化与共享。
- DBMS 统一管理完整性、安全性、并发与恢复。
- SQL 提供相对声明式的数据定义、操纵、查询和控制接口。

## 数据模型与数据库类型

| 类型 | 组织方式 | 特点 |
|---|---|---|
| 层次模型 | 树形父子关系 | 导航式访问，结构约束强 |
| 网状模型 | 一般图式记录联系 | 可表达多对多，但操作复杂 |
| 关系模型 | 表、键与关系运算 | 理论成熟，声明式 SQL 与数据独立性好 |
| 文档/键值/列族/图数据库 | 面向特定访问模型 | 横向扩展或特定查询占优，约束与事务能力依产品而异 |

关系型数据库以关系为基本结构，通过键和完整性约束表达联系，并由 SQL 完成声明式查询。

## 数据独立性

**物理独立性**指改变存储结构时尽量不改应用；**逻辑独立性**指改变全局逻辑模式时尽量不改外模式与应用。

> [!warning]
> 数据独立性不是“任何模式变化都完全无影响”，而是通过映像把变化隔离在较低层。

## Exam/Test Patterns

| 场景/关键词 | 回答 |
|---|---|
| 三级模式 | 外模式、模式、内模式 |
| 二级映像 | 隔离模式变化，分别支持逻辑与物理独立性 |
| DBMS 职责 | 定义、操纵、控制、恢复和安全 |
