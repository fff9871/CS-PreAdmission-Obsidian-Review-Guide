# 关系模型、键与完整性约束（★★★）

#database #relational-model #integrity-constraints

## Overview Table

| 项目 | 要点 |
|---|---|
| 关系 | 同类型元组构成的集合，可视为二维表 |
| 超码 | 能唯一标识元组的属性集 |
| 候选码 | 不可再约简的超码 |
| 主码 | 被选作主要标识的候选码 |
| 外码 | 引用另一关系候选码的属性集 |

## 三类关系完整性

| 约束 | 含义 |
|---|---|
| 实体完整性 | 主码属性非空，主码值唯一 |
| 参照完整性 | 外码为空或等于被参照关系中的有效键值 |
| 用户定义完整性 | 值域、格式与业务规则 |

## NULL 的语义

NULL 表示未知、不适用或尚未给出，并不等于 0 或空字符串。SQL 中与 NULL 的普通比较产生 UNKNOWN，应使用 IS NULL。

## 关系的基本性质

元组通常不以物理顺序区分，属性名唯一；理论关系不含重复元组，而 SQL 表在未使用 DISTINCT 时允许结果重复。

> [!warning]
> 主码可由多个属性组成；“主属性”是属于某个候选码的属性，不等于“主码中的属性”这一种选定结果。

## Exam/Test Patterns

| 场景/关键词 | 回答 |
|---|---|
| 主码与候选码 | 主码是候选码之一；候选码必须唯一且最小 |
| 外码能否为空 | 若业务与约束允许可以为空，否则必须引用存在的键 |
| 完整性层次 | 行内实体、表间参照、业务用户定义 |
