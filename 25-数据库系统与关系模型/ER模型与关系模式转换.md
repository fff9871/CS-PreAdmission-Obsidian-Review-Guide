# ER模型与关系模式转换（★★★）

#database #database-design #er-model

## Overview Table

| 项目 | 要点 |
|---|---|
| 实体 | 可独立识别的现实对象 |
| 属性 | 描述实体或联系的特征 |
| 联系 | 实体集之间的关联 |
| 基数 | 1:1、1:N、M:N |
| 弱实体 | 依赖拥有者实体和部分键才能标识 |

## 图形约定

实体常用矩形、属性用椭圆、联系用菱形；边上标出基数与参与约束。

## 转换规则

- 1:1：可把一方主码作为另一方外码，通常放在全参与或更合适的一侧。
- 1:N：把 1 端主码放到 N 端作为外码，并把联系属性放到 N 端。
- M:N：建立独立联系表，包含两端主码及联系自身属性。
- 多值属性：通常拆成独立关系。

## 设计检查

先确认实体边界和业务键，再检查联系基数、是否全参与、联系自身是否有属性。

> [!warning]
> 1:1 联系不是“任选一边放外键”后就结束；还要用 UNIQUE、NOT NULL 等约束表达基数和全参与。

## Exam/Test Patterns

| 场景/关键词 | 回答 |
|---|---|
| M:N 转换 | 新建联系表，组合外码常构成主码 |
| 1:N 外码位置 | 放在 N 端 |
| ER 合并冲突 | 检查命名、结构和约束冲突 |
