# 文件系统挂载、一致性与日志（★★★）

#operating-systems #file-system #journaling #crash-consistency

## Overview Table

| 概念 | 作用 |
|---|---|
| 挂载 | 把文件系统根接入统一目录树的挂载点 |
| 超级块 | 文件系统类型、大小、块和空闲状态等全局元数据 |
| 页/块缓存 | 缓存文件数据和元数据 |
| 日志 | 先记录可重做/撤销的更新，再更新主结构 |
| fsck | 扫描并修复元数据不一致 |

## 日志提交

    begin transaction
      → write log records/data
      → flush + commit record
      → checkpoint to home locations
      → reclaim log space

元数据日志只保护元数据结构；数据日志把文件数据也纳入事务，保证更强但写放大更大。写时复制文件系统通过写新块并原子切换根指针获得一致性。

## 持久化语义

应用需用 `fsync/fdatasync`、目录同步和原子 rename 等组合表达崩溃后的期望状态；仅关闭文件或 write 成功未必保证介质落盘。

> [!warning]
> 日志不等于备份，也不自动保证应用多文件事务。缓存、磁盘写回缓存和控制器都可能改变实际持久化顺序，必须依接口契约使用屏障/刷新。

## Exam/Test Patterns

| 问法 | 回答 |
|---|---|
| mount | 把一个文件系统接到目录树某节点 |
| journal 作用 | 崩溃后重放/回滚未完整事务，缩短恢复 |
| rename 原子性 | 同一文件系统内通常提供命名切换原子性，持久化仍需同步 |
