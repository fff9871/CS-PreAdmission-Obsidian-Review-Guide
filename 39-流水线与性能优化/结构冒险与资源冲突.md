# 结构冒险与资源冲突（★★★）

#computer-organization #pipeline #structural-hazard

## Overview Table

| 冲突资源 | 典型场景 | 解决方法 |
|---|---|---|
| 单端口存储器 | 同周期取指与数据访存 | 分离 I/D Cache、双端口或暂停 |
| 单个 ALU | 地址计算与算术指令同时需要 | 增加功能单元或调度暂停 |
| 寄存器端口 | 同周期读写数量超出端口能力 | 多端口寄存器堆、分时或暂停 |
| 总线/写回端口 | 多结果同周期写回 | 仲裁、增加端口、调整流水时序 |

## 形成条件

结构冒险发生在多条流水指令同一周期竞争**同一硬件资源**，而资源无法同时服务所有请求。

    I1: MEM阶段 ─┐
                  ├─ 同周期争用单端口存储器 → 冲突
    I2: IF阶段  ─┘

## 消除与规避

- 复制或分离资源：哈佛式 I-Cache/D-Cache。
- 增加端口或功能单元。
- 调整流水线阶段，让使用时间错开。
- 插入 stall，让一条指令等待。

> [!warning]
> 增加资源可以减少结构冒险，但会增加面积、功耗和布线复杂度；资源足够也不能消除数据冒险和控制冒险。

## Exam/Test Patterns

| 关键词 | 回答 |
|---|---|
| 两条指令争同一部件 | 结构冒险 |
| 取指与访数冲突 | 分离指令/数据存储或暂停 |
| 与数据冒险区别 | 前者是硬件资源不足，后者是操作数依赖 |
