# 多核、SMT与并行性（★★★）

#computer-organization #cpu #multicore #smt #parallelism

## Overview Table

| 层次 | 并行对象 | 典型机制 |
|---|---|---|
| 指令级并行 ILP | 同一线程中的多条指令 | 流水线、超标量、乱序执行 |
| 数据级并行 DLP | 多个数据元素 | SIMD、向量指令、GPU |
| 线程级并行 TLP | 多个软件线程 | 多核、SMT、细粒度多线程 |
| 任务级并行 | 相对独立任务/服务 | 多进程、分布式系统 |

## 核、硬件线程与软件线程

- **物理核心**拥有取指/执行资源和一定层次的私有或共享 Cache，可独立执行指令流。
- **硬件线程/逻辑处理器**保存独立的架构状态，如 PC 和寄存器映射，并共享同一核心的部分执行资源。
- **软件线程**是操作系统调度实体，被映射到可用逻辑处理器运行。

    四核八线程
      ├─ Core0: Thread0 / Thread1
      ├─ Core1: Thread2 / Thread3
      ├─ Core2: Thread4 / Thread5
      └─ Core3: Thread6 / Thread7

## SMT 为什么有效

当一个线程因 Cache miss、分支或执行单元不匹配而留下空槽，SMT 可从另一个线程发射指令，提高核心资源利用率。但两个硬件线程仍共享前端、执行端口、Cache 和内存带宽。

## 加速边界

- 程序需有足够可并行部分，受阿姆达尔定律限制。
- 锁竞争、同步、负载不均和通信会降低扩展效率。
- 共享 Cache、内存带宽和功耗限制会造成资源争用。
- 线程数超过有效并行度后，调度和上下文切换可能增加开销。

> [!warning]
> “四核八线程”表示四个物理核心提供八个逻辑处理器，不等于拥有八套完整执行资源，也不保证性能提升八倍。具体收益高度依赖工作负载。

## Exam/Test Patterns

| 问法 | 回答 |
|---|---|
| 核与线程区别 | 核是物理执行资源，硬件线程主要复制架构状态并共享核心资源 |
| SMT 作用 | 用其他线程填补流水线空槽，提高资源利用率 |
| 为什么不能线性加速 | 串行比例、同步、负载不均和共享资源瓶颈 |
