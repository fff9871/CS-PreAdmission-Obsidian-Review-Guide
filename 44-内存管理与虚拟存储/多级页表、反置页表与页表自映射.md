# 多级页表、反置页表与页表自映射（★★★）

#operating-systems #memory-management #page-table #multi-level-page-table #self-mapping

## Overview Table

| 结构 | 空间依据 | 特点 |
|---|---|---|
| 单级页表 | 虚拟页数 | 简单，但稀疏地址空间浪费大 |
| 多级页表 | 只为已使用区域分配下级表 | 节省连续表空间，增加访存层次 |
| 反置页表 | 物理页框数 | 全系统表更小，查找常需散列 |
| 哈希页表 | 虚拟页号散列 | 适合大而稀疏的地址空间 |
| 页表自映射 | 页目录项指向页目录自身 | 用固定虚拟区访问各级页表 |

## 多级拆分

    VA = [L1 index | L2 index | ... | offset]
          ↓          ↓
       directory → page table → frame

层数由虚拟地址位数、页大小和每张页表可容纳的条目数决定。更多层减少稀疏区空间浪费，但 TLB 未命中时页表遍历更长。

## 自映射思想

把某个顶级页表项映射回顶级页表物理页，使一段虚拟地址窗口递归解释为页目录和页表。操作系统因而可通过普通虚拟地址读写页表。

> [!warning]
> 自映射公式依具体页表层数、索引位宽和窗口位置，不能跨架构照搬；修改页表后还需按架构规则维护 TLB 一致性。

## Exam/Test Patterns

| 问法 | 回答 |
|---|---|
| 多级页表省什么 | 稀疏虚拟空间对应的页表内存 |
| 反置页表按什么建表 | 物理页框而不是虚拟页 |
| 自映射用途 | 用固定虚拟地址访问页表自身 |
