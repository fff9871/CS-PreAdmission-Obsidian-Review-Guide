# 请求分页与缺页处理（★★★）

#operating-systems #memory-management #virtual-memory #demand-paging #page-fault

## Overview Table

| 机制 | 作用 |
|---|---|
| 请求分页 | 仅在首次实际访问时调入页面 |
| 预取 | 根据预测提前调入可能访问的页面 |
| 写时复制 | fork 后共享只读页，首次写时复制 |
| 零页/按需分配 | 未写页面共享零页，写入时才给物理页 |

## 缺页处理流程

    访问 → PTE not-present → precise exception
       → 检查地址与权限
       → 找空闲页框或选择牺牲页
       → 脏页必要时写回
       → 从文件/交换区读入或零填充
       → 更新页表/TLB → 重启故障指令

有效访问时间可近似为：

`EAT = (1-p)×正常访存时间 + p×缺页服务时间`

因为磁盘/存储服务时间远大于内存，极小的缺页率也会显著影响性能。

> [!warning]
> 缺页可能由合法按需映射产生，也可能是非法访问。并非每次缺页都访问磁盘：匿名零页、已缓存文件页和 COW 都可能在内存中解决。

## Exam/Test Patterns

| 场景 | 处理 |
|---|---|
| 合法页未驻留 | 调页后重启指令 |
| 写共享只读 COW 页 | 分配复制后更新为可写 |
| 地址未映射 | 终止/信号或按策略扩展栈 |
