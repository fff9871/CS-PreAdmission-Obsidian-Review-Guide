# 银行家算法、安全状态、饥饿与活锁（★★★）

#operating-systems #deadlock #bankers-algorithm #liveness

## Overview Table

| 概念 | 现象 |
|---|---|
| 安全状态 | 存在一个顺序，使每个进程都能获得剩余需求并完成 |
| 死锁 | 一组进程永久等待组内成员才能释放的资源 |
| 饥饿 | 某个实体长期得不到资源，但系统整体仍可能前进 |
| 活锁 | 实体不断改变状态响应彼此，却没有有效进展 |

## 银行家算法

`Need = Max - Allocation`

1. 检查请求 `Request ≤ Need` 且 `Request ≤ Available`。
2. 试分配：更新 Available、Allocation、Need。
3. 用安全性算法寻找 `Need_i ≤ Work` 的进程，使其完成并释放 Allocation。
4. 若所有进程都可依次完成，才正式分配；否则回滚并等待。

    Work=Available → 找可完成进程 → Work+=Allocation
          ↑                │
          └──── 重复直到全部完成或无法继续

## 活性问题处理

老化缓解饥饿；公平锁/排队降低插队；随机退避可打破活锁；优先级继承缓解高优先级等待低优先级持锁者的问题。

> [!warning]
> 银行家算法依赖最大需求可知、资源实例可计数且可释放等假设，并不适合所有现代资源。安全序列可能不唯一，找不到安全序列才是不安全。

## Exam/Test Patterns

| 题型 | 步骤 |
|---|---|
| 求 Need | Max - Allocation |
| 判安全 | Work 推进并记录完成顺序 |
| 区分死锁/饥饿/活锁 | 集体等待 / 个体长期不得 / 持续动作无进展 |
