# 临界区、竞态条件与原子性（★★★）

#operating-systems #concurrency-control #critical-section #race-condition

## Overview Table

| 概念 | 含义 |
|---|---|
| 竞态条件 | 结果依赖并发执行的不可控时序 |
| 临界资源 | 一次只允许有限执行实体访问的资源 |
| 临界区 | 访问临界资源的代码段 |
| 原子操作 | 外部看来不可分割、无中间可见状态的操作 |

## 临界区协议

    entry section → critical section → exit section → remainder

正确互斥方案通常要求：

1. **互斥**：最多一个执行者进入临界区。
2. **进步**：临界区空闲时，候选者的选择不能无限推迟。
3. **有限等待**：一个请求者不会被无限次插队。
4. 不依赖对相对执行速度的不合理假设。

`count++` 常包含读、加、写三个步骤，并非天然原子；两个线程交错执行会发生丢失更新。

> [!warning]
> “单条高级语言语句”不等于原子操作；volatile 主要约束编译器/可见性语义，也不自动提供复合操作的互斥。互斥正确还不代表没有死锁或饥饿。

## Exam/Test Patterns

| 关键词 | 判断 |
|---|---|
| 结果随交错变化 | 竞态条件 |
| 一次只准一个进入 | 互斥要求 |
| 请求最终能进入 | 有限等待 |
