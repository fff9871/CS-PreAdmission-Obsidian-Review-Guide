# 管程与条件变量（★★★）

#operating-systems #concurrency-control #monitor #condition-variable

## Overview Table

| 机制 | 作用 |
|---|---|
| 管程 | 封装共享状态和操作，保证同一时刻仅一个活动者执行管程代码 |
| 条件变量 | 在某个条件不满足时释放管程锁并睡眠 |
| wait | 原子地释放锁、进入等待，醒来后重新取得锁 |
| signal/broadcast | 唤醒一个/全部等待者，不直接代表条件永久成立 |

## 标准用法

    lock(m)
    while not predicate:
        condition.wait(m)
    use shared state
    unlock(m)

必须在循环中复查谓词：唤醒到重新取得锁之间状态可能改变，也可能出现虚假唤醒。

## Hoare 与 Mesa 语义

| 语义 | signal 后谁立即运行 |
|---|---|
| Hoare | 被唤醒者立刻获得管程，signal 者让出 |
| Mesa | signal 者继续，被唤醒者稍后竞争锁 |

现代线程库多接近 Mesa 语义，因此“signal 后条件仍为真”不能作为保证。

> [!warning]
> 条件变量没有可累积的“许可”；无人等待时 signal 通常不会像信号量 V 那样留存计数。条件变量必须与受同一锁保护的状态谓词一起使用。

## Exam/Test Patterns

| 问法 | 回答 |
|---|---|
| wait 为何要原子释放锁 | 否则会丢失唤醒或让通知者无法修改条件 |
| 为什么用 while | 重获锁时条件可能再次为假或发生虚假唤醒 |
| 条件变量 vs 信号量 | 等待状态谓词的队列 vs 可累积许可计数 |
