# 死锁条件、资源分配图与处理策略（★★★）

#operating-systems #deadlock #resource-allocation #deadlock-handling

## Overview Table

| 必要条件 | 含义 |
|---|---|
| 互斥 | 资源不能同时共享使用 |
| 请求并保持 | 持有资源时继续请求其他资源 |
| 不可剥夺 | 资源只能由持有者主动释放 |
| 循环等待 | 进程—资源等待关系形成环 |

四个条件同时成立是死锁的必要条件；破坏任意一个即可预防。

## 资源分配图

    P → R：进程请求资源
    R → P：资源实例已分配给进程

每类资源只有一个实例时，图中有环等价于存在死锁；有多个实例时，有环只是可能死锁，需进一步检测。

## 四类策略

| 策略 | 做法 | 代价 |
|---|---|---|
| 忽略 | 假定罕见，由人工恢复 | 简单但可能停滞 |
| 预防 | 结构性破坏必要条件 | 利用率/并发度下降 |
| 避免 | 每次分配前保持安全状态 | 需最大需求等先验信息 |
| 检测与恢复 | 允许发生，定期检测后撤销/剥夺 | 检测和回滚成本 |

> [!warning]
> 不安全状态不等于已经死锁，而是存在导致死锁的未来分配序列；有环与死锁的等价性取决于每类资源实例数。

## Exam/Test Patterns

| 问法 | 回答 |
|---|---|
| 四个必要条件 | 互斥、请求并保持、不可剥夺、循环等待 |
| 有环是否死锁 | 单实例是；多实例不一定 |
| 资源有序申请 | 破坏循环等待 |
