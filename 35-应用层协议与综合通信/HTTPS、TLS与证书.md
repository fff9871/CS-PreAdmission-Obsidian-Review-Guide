# HTTPS、TLS与证书（★★★）

#computer-networks #application-layer #https #tls

## Overview Table

| 目标 | TLS 机制 |
|---|---|
| 机密性 | 对称加密保护应用数据 |
| 完整性 | AEAD/MAC 检测篡改 |
| 身份认证 | 服务器证书和数字签名；可选客户端证书 |
| 密钥协商 | 握手协商算法并建立会话密钥 |
| 防重放/顺序保护 | 记录层序号、握手随机数及协议机制 |

## 典型建立过程

    客户端 → ClientHello（版本、算法、随机数、密钥份额）
    服务器 → ServerHello + 证书 + 密钥份额 + 签名
    客户端 → 验证证书链、主机名、有效期和签名
    双方   → 派生会话密钥 → 加密HTTP数据

对称加密速度快，适合大量数据；非对称密码和签名主要用于身份认证与密钥协商。证书由受信任 CA 签发，把公钥与域名身份绑定。

## HTTP 与 HTTPS

| 维度 | HTTP | HTTPS |
|---|---|---|
| 传输保护 | 明文语义 | HTTP over TLS |
| 默认端口 | 80 | 443 |
| 身份验证 | 协议本身不提供 | 通常验证服务器证书 |
| 防篡改 | 协议本身不提供 | TLS 提供完整性保护 |

> [!warning]
> HTTPS 保护传输通道，不保证网站业务本身可信，也不能阻止端点被入侵。证书验证必须同时检查信任链、域名、有效期和吊销/状态策略，不能只看“有证书”。

## Exam/Test Patterns

| 关键词 | 回答 |
|---|---|
| 为什么混合密码 | 非对称建立信任和密钥，对称加密高效传输数据 |
| 证书作用 | 由 CA 签名，把公钥与域名身份绑定 |
| HTTPS 能防什么 | 窃听、传输篡改和常规中间人；不等于业务无漏洞 |
