# FTP控制连接与数据连接（★★★）

#computer-networks #application-layer #ftp

## Overview Table

| 连接 | 用途 | 生命周期/端口 |
|---|---|---|
| 控制连接 | 登录、命令和响应 | 通常连接服务器 TCP 21，整个会话保持 |
| 数据连接 | 目录列表和文件内容 | 每次传输按主动/被动模式建立 |
| 主动模式 | 服务器主动连接客户端指定端口 | 对客户端 NAT/防火墙不友好 |
| 被动模式 | 客户端连接服务器开放的数据端口 | 更适合 NAT 和防火墙环境 |

## 双连接工作流

    Client ===== TCP 21 控制连接 ===== Server
       |                                  |
       +------ 单独的数据连接 ----------+
             列目录/上传/下载

FTP 使用带外控制，把命令与文件数据分离。控制连接保持会话状态，数据连接可针对每个传输重新建立。

## 与其他文件传输方式

| 协议 | 特点 |
|---|---|
| FTP | 明文控制与数据，双连接 |
| FTPS | FTP 外加 TLS，仍保留 FTP 语义 |
| SFTP | 基于 SSH 的独立协议，不是“FTP over SSH” |
| HTTP 下载 | 请求响应模型，易穿越代理和防火墙 |

> [!warning]
> 传统 FTP 的用户名、口令和数据可能明文传输。主动/被动模式描述的是数据连接发起方向，不代表是否加密。

## Exam/Test Patterns

| 问法 | 回答 |
|---|---|
| FTP 为什么两条连接 | 控制命令与文件数据分离 |
| 主动 vs 被动 | 数据连接由服务器发起 vs 客户端发起 |
| FTP 是否安全 | 传统 FTP 不加密；FTPS 与 SFTP 是不同安全方案 |
