# DNS域名系统与解析（★★★）

#computer-networks #application-layer #dns

## Overview Table

| 组件/概念 | 作用 |
|---|---|
| 根域名服务器 | 指引到相应顶级域服务器 |
| 顶级域服务器 | 管理 `.com`、`.cn` 等顶级域指引 |
| 权威服务器 | 保存某区域的权威资源记录 |
| 本地递归解析器 | 代表客户端查询并缓存结果 |
| TTL | 控制 DNS 记录可缓存时间 |

## 递归与迭代

    客户端 --递归请求--> 本地DNS
                         ├→ 根DNS：去问TLD
                         ├→ TLD：去问权威DNS
                         └→ 权威DNS：目标记录
    客户端 <--最终结果-- 本地DNS（同时缓存）

客户端通常向本地解析器发递归查询；本地解析器再按根、顶级域、权威服务器做迭代查询。缓存可显著减少时延和上游负载。

## 常见资源记录

| 类型 | 含义 |
|---|---|
| A / AAAA | 名称映射到 IPv4 / IPv6 地址 |
| CNAME | 别名映射到规范名称 |
| MX | 邮件服务器 |
| NS | 区域的权威域名服务器 |
| PTR | 反向解析 |

DNS 常用 UDP 53 端口；响应过大、区域传送或需要可靠连接时可使用 TCP。现代部署还可能使用 DoT/DoH 加密查询通道。

> [!warning]
> DNS 不是“根服务器直接返回最终 IP”的单一数据库。结果可能经过别名链、负载均衡和缓存；TTL 到期前缓存变更也可能暂时不可见。

## Exam/Test Patterns

| 关键词 | 回答 |
|---|---|
| 为什么分布式 | 避免单点与容量瓶颈，降低远距离查询并便于自治管理 |
| 递归 vs 迭代 | 递归者负责给最终答案；迭代者返回下一步线索 |
| DNS 使用 UDP 还是 TCP | 常规查询多用 UDP；大响应、区域传送等可用 TCP |
