# 数据库安全、权限与备份（★★★）

#database #database-security #backup

## Overview Table

| 项目 | 要点 |
|---|---|
| 身份认证 | 确认访问者是谁 |
| 授权 | 决定主体可对哪些对象执行哪些操作 |
| 审计 | 记录重要访问和变更 |
| 备份 | 保留可恢复的数据副本 |
| 加密 | 保护传输中与静态数据 |

## 最小权限

用户和应用只获得完成任务所需的最小权限；优先通过角色集中授权，并定期审计闲置或过宽权限。

## 备份策略

全量、增量和日志备份需组合；定义恢复点目标 RPO 与恢复时间目标 RTO，并进行异机存放和恢复演练。

## 备份、副本与镜像

备份用于保留历史恢复点；副本或数据库镜像主要提高可用性并缩短故障切换时间。误删除和逻辑损坏可能同步到副本，因此高可用副本不能替代独立、可回溯的备份。

## 安全与完整性

安全性关注防止未授权访问和篡改；完整性关注数据符合约束；恢复关注故障后回到正确状态，三者相互配合。

> [!warning]
> “有备份”不等于“可恢复”。只有经过校验、保留策略合理且定期演练的备份，才能证明满足恢复目标。

## Exam/Test Patterns

| 场景/关键词 | 回答 |
|---|---|
| GRANT/REVOKE | 授予和撤销对象权限 |
| RPO/RTO | 允许丢失多少数据与允许恢复多久 |
| SQL 注入 | 参数化查询，不能只靠字符串转义 |
