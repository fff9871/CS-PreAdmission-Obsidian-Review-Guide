# 日志、WAL与故障类型（★★★）

#database #recovery #write-ahead-logging

## Overview Table

| 项目 | 要点 |
|---|---|
| 事务故障 | 单个事务因逻辑错误、约束或主动回滚失败 |
| 系统故障 | 进程或机器崩溃，内存状态丢失 |
| 介质故障 | 磁盘或持久介质损坏 |
| UNDO | 撤销未提交事务的影响 |
| REDO | 重放已提交但未落盘的修改 |

## WAL 原则

与某数据页修改对应的日志必须先于该脏页写入稳定存储；事务提交前，其提交记录和必要 redo 日志必须持久化。

## 日志内容

常包含事务标识、对象或页标识、旧值/新值或逻辑操作，以及开始、提交、回滚等记录。

## 故障对应

事务故障主要 UNDO；系统崩溃通常按日志判断哪些事务要 REDO、哪些要 UNDO；介质故障还需要备份加归档日志。

> [!warning]
> UNDO/REDO 的具体选择取决于缓冲策略和日志算法；面试应先说明目标，再说明采用的恢复模型。

## Exam/Test Patterns

| 场景/关键词 | 回答 |
|---|---|
| WAL | 日志先于数据页落盘 |
| 原子性与持久性 | UNDO 支撑前者，REDO 支撑后者 |
| 介质故障 | 备份加日志恢复 |
