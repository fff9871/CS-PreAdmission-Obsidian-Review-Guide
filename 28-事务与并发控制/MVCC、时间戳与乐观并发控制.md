# MVCC、时间戳与乐观并发控制（★★★）

#database #transactions #mvcc

## Overview Table

| 项目 | 要点 |
|---|---|
| MVCC | 保存多个版本，让读者按可见性规则读取快照 |
| 时间戳排序 | 按事务时间戳约束读写顺序 |
| 乐观控制 | 先执行，提交前验证冲突 |
| 悲观控制 | 先加锁再访问可能冲突的数据 |

## MVCC 读写关系

读通常不阻塞写，写通常也不阻塞快照读；写写冲突仍需检测或加锁。版本包含创建/删除事务信息，由可见性规则决定能否读取。

## 乐观控制阶段

读与计算 → 验证 → 写入/提交

适合冲突少、读多写少的工作负载；冲突高时频繁回滚会浪费工作。

## 版本回收

旧版本不能无限保留，需要在确认无活动事务再需要后回收；长事务可能阻碍回收并放大存储。

> [!warning]
> MVCC 不是“完全无锁”，也不会自动消除所有写冲突、幻读和业务竞态；具体保证取决于隔离级别与实现。

## Exam/Test Patterns

| 场景/关键词 | 回答 |
|---|---|
| MVCC 优势 | 减少读写互相阻塞 |
| 乐观与悲观 | 冲突少用验证，冲突多可先锁定 |
| 长事务风险 | 长期占用旧快照，阻碍版本清理 |
