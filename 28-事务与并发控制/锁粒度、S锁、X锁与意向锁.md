# 锁粒度、S锁、X锁与意向锁（★★★）

#database #transactions #locking

## Overview Table

| 项目 | 要点 |
|---|---|
| S 锁 | 读锁；多个事务可兼容持有 |
| X 锁 | 写锁；与其他 S/X 锁冲突 |
| IS/IX | 表级意向标志，表示将在下层加 S/X 锁 |
| 锁粒度 | 行、页、表等被保护对象范围 |

## 兼容性要点

| 已持有/申请 | S | X |
|---|---|---|
| S | 兼容 | 冲突 |
| X | 冲突 | 冲突 |

意向锁用于多粒度层次的快速冲突判断，不直接代替行上的 S/X 锁。

## 粒度权衡

粒度小：并发度高，但锁数量、管理和内存开销大。粒度大：管理简单，但冲突概率高。锁升级会把许多细粒度锁合并为粗粒度锁。

## 三级封锁协议

| 协议 | 规则 | 主要避免的问题 |
|---|---|---|
| 一级 | 写前加 X 锁，并持有到事务结束 | 丢失修改 |
| 二级 | 一级基础上，读前加 S 锁，读完可释放 | 再避免脏读 |
| 三级 | 一级基础上，读锁也持有到事务结束 | 再避免不可重复读 |

三级封锁协议是按保护强度递增的教材分类；它与“增长/收缩阶段”的两段锁协议不是同一个分类维度。

## 行锁条件

数据库能否使用行级锁常取决于存储引擎、访问路径和谓词；缺少合适索引时，扫描和锁定范围可能扩大。

> [!warning]
> IX 表示“打算在下层加排他锁”，自身是表级锁；它并不等价于已经把整张表排他锁住。

## Exam/Test Patterns

| 场景/关键词 | 回答 |
|---|---|
| S/X 兼容 | S-S 可兼容，其余涉及 X 通常冲突 |
| 意向锁目的 | 让表级锁无需逐行检查下层锁 |
| 粒度取舍 | 并发度对管理开销 |
