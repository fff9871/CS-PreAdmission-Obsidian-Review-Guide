# 并发异常与隔离级别（★★★）

#database #transactions #isolation-levels

## Overview Table

| 项目 | 要点 |
|---|---|
| 脏读 | 读到另一个未提交事务的数据 |
| 不可重复读 | 同一行两次读取值不同 |
| 幻读 | 同一谓词范围两次读取出现或消失行 |
| 丢失更新 | 后写覆盖前写，使一次修改消失 |

## 标准隔离级别

| 级别 | 脏读 | 不可重复读 | 幻读 |
|---|---|---|---|
| Read Uncommitted | 可能 | 可能 | 可能 |
| Read Committed | 防止 | 可能 | 可能 |
| Repeatable Read | 防止 | 防止 | 标准定义下可能 |
| Serializable | 防止 | 防止 | 防止 |

## 隔离与性能

更强隔离通常减少并发异常，但可能增加等待、冲突或版本维护成本。具体 DBMS 的实现可能比标准最低保证更强。

## 快照语义

MVCC 下的一致性读可读取某个快照；当前读、锁定读和不同数据库的 Repeatable Read 语义需分别说明。

> [!warning]
> 不可重复读关注同一行值变化；幻读关注满足谓词的行集合变化。二者容易混淆。

## Exam/Test Patterns

| 场景/关键词 | 回答 |
|---|---|
| 脏读 | 读取失败事务尚未提交的修改 |
| 不可重复读与幻读 | 一条记录的值变化对结果集合成员变化 |
| 隔离级别 | 强度越高异常越少，代价通常越高 |
