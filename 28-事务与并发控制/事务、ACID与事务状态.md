# 事务、ACID与事务状态（★★★）

#database #transactions #acid

## Overview Table

| 项目 | 要点 |
|---|---|
| 原子性 | 事务操作全部完成或全部撤销 |
| 一致性 | 事务把数据库从一个满足约束的状态带到另一个满足约束的状态 |
| 隔离性 | 并发事务的中间影响按隔离保证被控制 |
| 持久性 | 提交结果在故障后仍可恢复 |

## ACID 的实现支撑

| 性质 | 典型机制 |
|---|---|
| 原子性 | UNDO、回滚 |
| 一致性 | 正确事务逻辑、完整性约束及其余三项共同保证 |
| 隔离性 | 锁、时间戳、MVCC、串行化协议 |
| 持久性 | REDO、WAL、稳定存储 |

## 事务状态

active → partially committed → committed
       ↘ failure → aborted → restart / terminated

事务执行完最后一条语句不等于已经持久提交，还要完成提交协议。

## 边界

COMMIT 建立持久提交点；ROLLBACK 撤销到事务开始或保存点，具体能力依 DBMS。

> [!warning]
> 一致性是最终正确性目标，不是某一个单独日志或锁机制独自保证的属性。

## Exam/Test Patterns

| 场景/关键词 | 回答 |
|---|---|
| ACID | 定义后补充各自机制 |
| 原子性与持久性 | 分别依赖 UNDO 与 REDO 的核心方向 |
| COMMIT | 成功边界；此前中间状态仍可能回滚 |
