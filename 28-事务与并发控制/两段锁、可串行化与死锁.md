# 两段锁、可串行化与死锁（★★★）

#database #transactions #two-phase-locking #serializability

## Overview Table

| 项目 | 要点 |
|---|---|
| 冲突操作 | 不同事务对同一数据的读写或写写 |
| 冲突可串行化 | 通过交换不冲突操作可变成某个串行调度 |
| 2PL | 先增长只加锁，后收缩只解锁 |
| 严格 2PL | 排他锁持有到提交或回滚 |
| 死锁 | 事务形成循环等待 |

## 优先图判定

为每个事务建顶点；若冲突操作在调度中 Ti 先于 Tj，则加边 Ti→Tj。图无环当且仅当调度冲突可串行化。

## 2PL 与串行化

遵守基本两段锁可保证冲突可串行化，但不能保证无死锁。严格 2PL 还可避免级联回滚并简化恢复。

## 死锁处理

- 预防：破坏等待条件，如统一加锁顺序或时间戳策略。
- 检测：构造等待图，发现环后选择牺牲事务回滚。
- 超时：工程上简单但可能误判。

> [!warning]
> “可串行化”不要求事务真的串行执行，而是并发结果等价于某种串行顺序。

## Exam/Test Patterns

| 场景/关键词 | 回答 |
|---|---|
| 2PL 保证什么 | 冲突可串行化，不保证无死锁 |
| 等待图 | 有环表示死锁 |
| 严格 2PL | 写锁持有至结束，避免读到未提交写入 |
