# 存储层次与局部性（★★★）

#computer-organization #memory-hierarchy #locality

## Overview Table

| 层次 | 速度 | 容量 | 位成本 | CPU 可见性 |
|---|---|---|---|---|
| 寄存器 | 最高 | 最小 | 最高 | 指令直接访问 |
| Cache | 很高 | 小 | 高 | 通常由硬件自动管理 |
| 主存 | 中等 | 较大 | 中等 | 通过地址访问 |
| 辅存 | 较低 | 很大 | 低 | 经 I/O 和虚拟存储机制访问 |

## 层次结构目标

利用程序的局部性，让常用数据靠近 CPU，使系统获得“接近上层速度、接近下层容量与成本”的综合效果。

    CPU ↔ Registers ↔ Cache ↔ Main Memory ↔ SSD/HDD
          快、小、贵  ─────────────→ 慢、大、便宜

## 局部性

| 类型 | 含义 | 示例 |
|---|---|---|
| 时间局部性 | 最近访问的数据/指令很快再次访问 | 循环变量、热点代码 |
| 空间局部性 | 访问某地址后倾向访问邻近地址 | 顺序数组、连续指令 |

Cache 以块为单位搬运利用空间局部性，保留近期块利用时间局部性；虚拟存储以页为单位在主存和辅存间调度。

> [!warning]
> 局部性是统计规律，不是保证。随机访问、超大工作集和冲突访问会显著降低命中率；块越大也可能带来污染和更高缺失代价。

## Exam/Test Patterns

| 问法 | 回答 |
|---|---|
| 为什么要多级存储 | 速度、容量和成本不能同时最优 |
| Cache 依据 | 时间与空间局部性 |
| Cache-主存 vs 主存-辅存 | 前者缓解速度差，后者扩展可用地址空间与容量 |
