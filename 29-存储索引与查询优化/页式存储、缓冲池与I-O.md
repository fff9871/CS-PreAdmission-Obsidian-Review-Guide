# 页式存储、缓冲池与I-O（★★★）

#database #storage-engine #buffer-pool

## Overview Table

| 项目 | 要点 |
|---|---|
| 页 | 数据库与磁盘交换数据的常见基本单位 |
| 缓冲池 | 缓存热点页，减少磁盘 I/O |
| 记录 | 页内保存的行或索引项 |
| 局部性 | 相邻或近期访问的数据更可能再次被访问 |

## 访问路径

SQL → 执行算子 → 缓冲池查页
                     ├─ 命中：直接访问内存页
                     └─ 未命中：从磁盘读页并可能淘汰旧页

## 为何关注 I/O

内存比较通常远快于随机磁盘访问。B+ 树通过高扇出降低高度，覆盖索引通过少读数据页减少 I/O。

## 页分裂与写放大

索引页空间不足时可能分裂；随机插入可能增加页分裂、碎片与写放大。顺序键写入局部性好，但也可能形成热点。

> [!warning]
> 查询耗时不只取决于算法复杂度；页访问数、随机/顺序 I/O、缓存命中率和并发等待常更关键。

## Exam/Test Patterns

| 场景/关键词 | 回答 |
|---|---|
| 数据库为何用 B+ 树 | 高扇出降低页 I/O |
| 缓冲池命中 | 避免物理读，但仍有内存访问和并发控制成本 |
| 顺序 I/O | 通常比大量随机 I/O 更友好 |
