# MySQL存储引擎与选型（★★★）

#database #mysql #storage-engine

## Overview Table

| 项目 | 要点 |
|---|---|
| InnoDB | 事务、行级锁、崩溃恢复、外键，MySQL 常用默认引擎 |
| MyISAM | 传统非事务引擎，表级锁，适合特定只读或历史场景 |
| Memory | 数据主要在内存，重启后数据不持久 |
| Archive | 面向归档写入与压缩的特定引擎 |

## 选型维度

是否需要事务和崩溃恢复、读写比例、并发模式、持久性、索引能力、外键需求以及 MySQL 版本支持。

## InnoDB 关键点

聚簇组织、MVCC、redo/undo、行级锁与缓冲池共同支撑通用 OLTP。二级索引叶项通常保存主键，因此过宽主键会放大二级索引。

## 版本意识

资料中的引擎功能可能随版本变化。工程回答应先给稳定原则，再说明具体版本和配置需要查文档。

> [!warning]
> “只有 InnoDB 支持事务”是过度概括；MySQL 生态和版本中可能存在其他事务引擎。面试重点应放在 InnoDB 与常见替代引擎的能力差异。

## Exam/Test Patterns

| 场景/关键词 | 回答 |
|---|---|
| OLTP 默认选型 | 通常 InnoDB |
| Memory 风险 | 进程或服务重启后数据不持久 |
| 主键宽度 | 会影响聚簇记录和二级索引大小 |
