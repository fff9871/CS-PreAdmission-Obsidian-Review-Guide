# 分布式文件系统、一致性与容错（★★★）

#operating-systems #distributed-systems #distributed-file-system #consistency

## Overview Table

| 主题 | 关键问题 |
|---|---|
| 命名 | 全局命名空间、位置透明、挂载 |
| 缓存 | 客户端/服务端缓存与失效 |
| 复制 | 可用性、读扩展和一致性协议 |
| 一致性模型 | 强一致、顺序/因果、最终一致等 |
| 容错 | 超时、重试、副本、日志与故障恢复 |

## 复制读写

    client → coordinator/leader → replicas
                ↓ quorum/commit rule
             acknowledge result

一致性越强，通常越需要协调并受网络延迟/分区影响；弱一致可提升可用性和离线能力，但把冲突处理暴露给应用。

## 缓存语义

关闭时写回、会话语义、租约/回调失效和版本检查是常见方案。客户端崩溃、断网和时钟偏差会影响租约与锁的正确性。

> [!warning]
> CAP 讨论的是网络分区发生时，一致性与可用性的取舍，不是平时只能三选二的口号；复制也不是备份，错误可能同步传播到所有副本。

## Exam/Test Patterns

| 问法 | 回答 |
|---|---|
| 分布式缓存难点 | 多副本失效、并发写和部分失败 |
| 强一致代价 | 跨节点协调和分区时可用性下降 |
| 副本作用 | 容错、读扩展和就近访问，同时增加一致性复杂度 |
