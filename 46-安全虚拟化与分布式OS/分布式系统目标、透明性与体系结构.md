# 分布式系统目标、透明性与体系结构（★★★）

#operating-systems #distributed-systems #transparency #distributed-architecture

## Overview Table

| 目标 | 含义 |
|---|---|
| 资源共享 | 远程数据、计算和设备可统一访问 |
| 透明性 | 尽量隐藏位置、迁移、复制、并发和故障差异 |
| 开放性 | 标准接口、互操作和可扩展实现 |
| 可扩展性 | 规模、地理和管理域扩大时仍有效 |
| 容错 | 部分节点/网络失败时继续提供受控服务 |

## 体系结构

| 架构 | 特点 |
|---|---|
| 客户端—服务器 | 服务集中、接口明确 |
| 多层 | 表示、逻辑、数据分层扩展 |
| P2P | 节点角色对等、去中心化 |
| 集群 | 紧耦合节点协同提供计算/服务 |
| 分布式 OS | 试图提供单一系统映像与全局资源管理 |

    nodes + network + middleware
            ↓ naming / communication / consistency
      users see coherent services

完全透明并不总是最佳：隐藏网络延迟或部分失败可能诱导错误假设，接口应在必要处暴露超时、重试和一致性语义。

> [!warning]
> 分布式系统没有共享的完美全局时钟，网络可能分区，远程调用也不具备本地函数调用的可靠性与低延迟。

## Exam/Test Patterns

| 问法 | 回答 |
|---|---|
| 位置透明 | 使用资源不必知道其物理位置 |
| 复制透明 | 多副本对用户呈现一致资源视图 |
| 单一系统映像 | 多节点表现为统一计算系统 |
