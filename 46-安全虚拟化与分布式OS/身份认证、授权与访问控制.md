# 身份认证、授权与访问控制（★★★）

#operating-systems #system-security #authentication #authorization

## Overview Table

| 环节 | 回答的问题 | 典型机制 |
|---|---|---|
| Identification | 你声称是谁 | 用户名、主体标识 |
| Authentication | 如何证明身份 | 密码、令牌、生物特征、密钥 |
| Authorization | 允许做什么 | ACL、角色、能力、策略 |
| Accounting/Audit | 做了什么 | 日志、审计轨迹、不可否认性 |

## 认证因素

| 因素 | 示例 |
|---|---|
| 所知 | 密码、PIN |
| 所有 | 智能卡、OTP 令牌、私钥 |
| 所是 | 指纹、人脸 |

多因素认证应组合不同因素，而不是仅使用两个密码。密码应使用带盐、成本可调的专用哈希保存，并配合速率限制和安全恢复流程。

## 访问检查

    subject + requested operation + object
                 ↓ policy / credentials / context
              allow or deny → audit

最小权限、默认拒绝、职责分离和完全仲裁是常见设计原则。

> [!warning]
> 认证成功不代表拥有任意权限；加密也不自动解决授权。审计日志必须考虑完整性、隐私、时间同步和访问控制。

## Exam/Test Patterns

| 问法 | 回答 |
|---|---|
| 认证 vs 授权 | 证明身份 vs 判断权限 |
| 多因素 | 来自不同因素类别的凭据 |
| 最小权限 | 只授予完成任务所需最少权限和时间 |
